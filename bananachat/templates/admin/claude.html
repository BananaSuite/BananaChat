Pool quota

{{ csrf() }}

Token-based. Claude models do not count toward the service (pool) limits by default; each has its own strict 5-hour token window (weekly optional, off by default). While less than half of the pooled subscription quota is left, their limits shrink automatically — on top of dynamic adjustment for demand, active people and usage pattern. Opus is strictest, then Sonnet, then Haiku.

Pooled remaining: 5-hour {% if quota.window_left is none %}unknown{% else %}{{ (quota.window_left * 100) | round(1) }}%{% endif %} · weekly {% if quota.weekly_left is none %}unknown{% else %}{{ (quota.weekly_left * 100) | round(1) }}%{% endif %} · {{ quota.accounts }} active account(s), {{ quota.usable if quota.usable is defined else quota.accounts }} with quota left now.

The pool is the sum of its active accounts: one exhausted subscription only removes its share. Requests go to the highest-priority account with quota left; when the Claude site reports an account out of quota (or it fails), it rests and the next account answers. With no account able to answer, Claude models count as used up and the chat falls back to local models (Limits → Services → Model fallback).
