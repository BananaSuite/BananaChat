Workers

Volunteer PCs that run chat and API requests with their own Ollama.

{% if not workers_enabled %}
{{ icon("alert") }}

Remote workers are turned off on this server. No request is sent to a worker, and workers are told the feature is disabled (HTTP 503). Set BC_WORKERS_ENABLED=1 in the server configuration and restart to turn them on. You can register workers and install their tokens before that.

{% endif %}
{{ icon("shield") }}

Worker operators can read the prompts sent to them. A request answered by a worker — including the conversation history and any attached images — is processed on that person’s computer, where it can be logged or copied. Register only machines whose owners you trust with your users’ conversations, and tell your users that some answers are produced on volunteer hardware.

{{ icon("chevron-down") }}How requests reach workers

Administrators’ own requests always use the local server. A worker gets a request only when it is online, not gaming and advertises the model; if none takes it within {{ claim_timeout }} seconds, or it fails before answering, the local server answers instead. A worker that fails or stalls a job is paused: it gets no job for a minute, twice as long after each further failure (up to an hour), until it completes one again. The server deletes a job’s prompt as soon as it ends and the job record after an hour.

Maintenance access

{% if not remote_enabled %}

Off. With BC_WORKER_REMOTE_ACCESS=1 (and BC_WORKERS_ENABLED=1) administrators can reach worker PCs for maintenance through tunnels the workers open themselves: a terminal and the screen (VNC) in the browser, and SSH, VNC or RDP from their own computer with the connect helper. No port is opened on the worker's network, and each worker's owner decides what can be reached.

{% else %}

Open a worker's Manage page for its terminal and screen. For SSH, VNC and RDP clients on your own computer, download the connect helper (one Python file, Linux, macOS and Windows) and create an access key here. Each worker has an address in the virtual network {{ subnet }}, reachable through the helper wherever the worker is.

python bananachat_connect.py login {{ server_url }}
python bananachat_connect.py list
ssh -o ProxyCommand="python bananachat_connect.py proxy %h %p" user@WORKER-ADDRESS
python bananachat_connect.py socks --listen 127.0.0.1:1080

Set up a worker PC

  1. Register the worker above and copy its token.
  2. On the PC, install Ollama and pull the models it should serve, for example ollama pull qwen3:4b. Use the same model names as this server.
  3. Copy the worker/ folder of this server’s source code to the PC (Python 3.9 or newer is needed; nothing else).
  4. Run python bananachat_worker.py install in that folder. It creates the settings file and a background service.
  5. Edit the settings file (~/.config/bananachat-worker.env, or %APPDATA%\BananaChat\bananachat-worker.env on Windows): 
    BC_SERVER_URL={{ server_url }}
BC_WORKER_TOKEN=<the token>
BC_WORKER_NAME=My gaming PC
  6. Start it with python bananachat_worker.py start and watch it appear here as online.

The worker steps aside when its owner plays games and lowers its priority while they use the PC. See docs/workers.md in the source code for details.
