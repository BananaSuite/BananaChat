{{ icon("shield") }} Backups

Backups are made on the server with the management tool, which briefly pauses the site so the copy is consistent. Run these commands in a terminal on the server:

A complete local backup (with model files)
{{ command("sudo bananachat backup") }}
A small backup without model files
{{ command("sudo bananachat backup --exclude-model-weights --output /root/chat-data.tar.gz") }}
Restore a backup
{{ command("sudo bananachat restore /root/chat-data.tar.gz") }}

Encrypted, scheduled backups to a private GitHub or Forgejo repository are also available (sudo bananachat backups configure, then sudo bananachat backups enable); see docs/backups.md. Keep an offline copy of the recovery key. Backups without model files record which models were installed: after a restore, the Models page offers to download them again.

{{ icon("download") }} Database export

Downloads a consistent copy of the database ({{ database_size | filesize if database_size is not none else "size unknown" }}, schema version {{ schema_version }}) as a .tar.gz file. Use it to move the accounts, chats and settings of an older installation to a new managed server:

{{ command("sudo bananachat restore --legacy-database /root/bananachat_export.tar.gz") }}
{{ icon("alert") }}

The file contains every account, password hash and chat. Store and transfer it as securely as the server itself, and delete it when you are done.

It does not include model files, uploaded audio, the secret key or the server configuration; copy those separately while the service is stopped.

Without the secret key, accounts that use two-step verification sign in on the new server with a recovery code and set it up again.

{{ csrf() }} {{ reauth_field("export-reauth") }}

Importing through the browser is not possible: a restore must stop every server process, which only the management tool can do safely.
